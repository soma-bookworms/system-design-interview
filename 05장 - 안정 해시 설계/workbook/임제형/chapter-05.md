# **05장 - 안정 해시 설계**

---

# 개요

## 해시 키 재배치`rehash` 문제
- N개의 서버로 트래픽을 균등하게 나눌때는, `hash(key)`를 N으로 나누는 모듈러 연산을 하면 되는데
- 서버가 추가되거나 기존 서버가 삭제되면 `hash(key)`는 바뀌지 않지만 모듈러 연산 결과가 달라질 것이다.
- 클라이언트가 전에 접속한 서버와 다른 엉뚱한 곳에 배치되는 일이 발생하는 것

## 안정 해시
> 해시 테이블 크기가 조정될 때 평균저그로 오직 k/n개의 키만 재배치하는 해시 기술

> 여기서 k는 키의 개수이고 n은 슬롯(위 예시에서는 서버 개수)의 개수이다.

## 해시 공간과 해시 링

- SHA-1 해시 공간 `0 ~ 2^160-1`을 예시로 들었을 때, 해시 공간의 양 끝을 이어 링으로 만든다고 생각해보자
- 해시 함수 f(서버 0)을 통해 이 해시 링 위 어떤 지점에 서버 0을 할당할 지 정할 수 있다.
- 위와 같은 방식으로 N개의 서버를 해시 링 위에 놓는다.
- 이후 f(클라이언트 A)를 통해 특정 요청의 해시 링 지점을 찾고, 시계 방향으로 가장 가까운 서버에 요청을 배치한다.
- Pros: 모듈러 연산에서 문제가 된, 다수의 클라이언트가 모두 엉뚱한 곳에 배치되는 일은 막았다.
- Cons: 서버가 추가되거나 삭제될 때, 각 서버에 할당되는 파티션의 크기를 일정하게 유지하는게 불가능하다.

## 가상 노드
> 실제 노드 또는 서버를 가리키는 노드로서, 하나의 서버는 링 위에 여러 개의 가상 노드를 가질 수 있다.
- 서버 0이 해시 링위에 s0_0, s0_1, s0_2 처럼 여러개의 지점을 사용한다.
- 가상 노드 자체는 여러 서버간 순서가 뒤섞여, 하나의 서버가 사라져도 나머지 서버에 상대적으로 균등하게 분배된다.
- Pros: 가상 노드를 늘릴 수록 키의 분포가 점점 더 균등해진다. 즉, 파티션 크기가 일정해진다.
- Cons: 가상 노드 데이터를 저장할 공간은 더 많이 필요하게 될 것이다.

## 안정 해시의 이점

- 서버가 추가되거나 삭제될 때 재배치되는 키의 수가 최소화된다.
- 데이터가 보다 균등하게 분포하게되어 수평적 규모 확장성을 달성하기 쉽다.
- 핫스팟 키 문제를 줄인다. 균등하게 데이터를 분배하여 한 곳에 몰리는 상황을 방지하는 것

## 실사용 사례

- 아마존 DynamoDB 파티셔닝 관련 컴포넌트
- 아파치 카산드라 클러스터 데이터 파티셔닝
- 디스코드 채팅
- 아카마이 CDN
- 마글레브 네트워크 부하 분산기
