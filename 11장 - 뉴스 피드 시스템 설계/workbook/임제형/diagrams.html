구조도 초안

뉴스 피드 구조도 세 장

박스 제목은 역할, 아래 작은 글씨가 실제 이름이다 — Tweetypie·Gizmoduck 같은 건 사내 서비스 코드네임이고, Redis·Kafka·MySQL·Lucene은 오픈소스 제품이다. 같은 화법으로 맞췄다. 주황은 피드 발행, 청록은 뉴스 피드 생성, 겹친 사각형은 복제된 저장소, 점선은 비동기 또는 우회 경로.

A

Twitter 2012 — 팬아웃 + 셀럽 우회

  • 요청 수신부 TFE · Twitter Front End — 트윗을 받아 메시지 큐에 넣고 최대 145ms 안에 연결을 끊는다. 이 경로는 Ruby로 구현돼 있고, 목표는 클라이언트 연결을 최대한 빨리 놓아주는 것이다.
  • 메시지 큐 Kestrel — 트위터가 직접 만들어 공개한 메시지 큐. 쓰기 요청과 팬아웃 작업을 끊어주는 지점이다. 이 큐가 있어서 팬아웃이 5분 걸려도 글쓴이는 즉시 응답을 받는다.
  • 팬아웃 데몬 fanout daemon — 메시지 큐에서 꺼내 처리하는 상주 프로세스. 새 트윗을 감지해 팔로워들의 타임라인에 밀어넣는다. 메시지 큐를 거치므로 작성자는 이 작업을 기다리지 않는다. 팬아웃 목표는 5초인데 대형 계정이 글을 쓰면 못 맞춘다. 캐시에 쓸 때는 응답을 기다리지 않고 4,000개씩 연달아 쏜다(파이프라이닝) — 병목이 Redis 처리 속도가 아니라 네트워크 왕복 시간이기 때문.
  • 팔로워 관계 저장소 Flock · FlockDB — 팔로우 관계만 저장하는 전용 DB. MySQL 위에 엣지를 인접 리스트로 얹었다. “A의 팔로워 전부”를 빠르게 주는 게 목적이고, 다단 탐색은 지원하지 않는다. 2010년 4월 엣지 130억+.
  • 타임라인 캐시 Redis — 회원마다 “내 타임라인에 뜰 트윗 ID 목록”을 들고 있다. 본문은 없다.
  • 대형 계정 — 팔로워가 너무 많아 팬아웃 대상에서 뺀 계정. 이 트윗은 읽을 때 따로 가져온다.
  • 타임라인 조회 Timeline Service — 요청한 회원의 ID 목록을 Redis에서 꺼내온다. 복제본 3벌 중 어디서 읽을지 해시링으로 고른다.
  • 머지 — Redis에서 온 목록에 대형 계정 트윗을 시간순으로 끼워넣는다. push와 pull이 여기서 합쳐진다.
  • 본문 채우기 hydration — ID만 있는 목록을 실제 트윗 내용과 작성자 정보로 채운다.
  • 트윗 본문 조회 Tweetypie · Twemcache — 트윗 읽기·쓰기 서비스. 최근 한 달 반치를 별도 분산 캐시 클러스터에 올려둔다.
  • 유저 정보 조회 Gizmoduck · Twemcache — 이름·프로필 등을 제공하는 사용자 서비스. 별도 분산 캐시 클러스터를 쓴다.
B

LinkedIn FollowFeed — 팬아웃 없음

  • 활동 변경 스트림 Kafka — 공유·좋아요·댓글 등 콘텐츠의 생성·수정 이벤트가 지나가는 통로.
  • 랭킹 신호 스트림 Kafka — 품질 판정과 점수 계산에 쓰는 피처가 흐르는 별도 통로.
  • 파티션 배분 Partitioner — 이벤트를 각 노드가 담당하는 파티션 번호 범위에 맞춰 다시 내보낸다. 덕분에 노드는 “어디로 보낼지” 판단할 필요가 없다.
  • 관심 대상 조회 — 상위 관계 서비스에서 열람자가 팔로우한 회원·회사·학교 목록을 받아온다. FollowFeed 바깥의 의존성이다.
  • 타임라인 인덱스 followfeed-storage — 타임라인을 저장하고, 볼 권한 확인과 점수 계산까지 노드 안에서 끝내 상위 몇 건만 올린다.
  • 타임라인 조회 Broker / followfeed-query — 어느 노드에 물어야 하는지 계산해 동시에 질의하고, 돌아온 결과를 합쳐 중복을 제거한다.
  • 피드 조립 Feed Mixer — FollowFeed 위의 중간 서비스. 여러 후보 목록을 하나로 합치고, 같은 작성자 글이 연달아 나오지 않도록 최종 순서를 조정한다.
  • D2 — 지금 살아 있는 노드 주소를 Zookeeper에서 조회하는 장치. 노드가 죽거나 늘어나도 브로커를 다시 배포할 필요가 없다.
C

LinkedIn FollowFeed — 타임라인 저장 노드 내부

두 구조도는 같은 시각 규칙을 쓴다 — 주황=쓰기·발행, 청록=읽기·생성, 겹친 사각형=복제 저장소, 점선=비동기·우회.
